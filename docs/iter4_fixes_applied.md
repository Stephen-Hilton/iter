## Decisions taken 2026-09-28 (Stephen)

- **Lease enforcement is always on; the switch is gone.** `lock_lease_enforce` was removed from the project record, iter_core, iter_data and the engine. A lock goes only to a running item and carries its run's lease; a row without a live lease blocks nobody; locks live at most 600 s unless renewed; the engine's lock sweep always deletes (the `dry_run` flag stays on the route, for a person inspecting the table).
- **600 s lease, renewed every 60 s**, kept. Renewal is on the engine's timer, not on agent activity: a silent two-hour turn keeps its locks while the engine process is alive and reaches iter_data. (`ITER_LOCK_RENEW_EVERY_SEC` overrides the 60 s, for tests.)
- **Lapsed rows** (a renewal renews fewer rows than the item has lockdirs — they expired during an outage longer than the lease and were swept): the engine re-takes every path under the same lease; if all are free the run continues with a doc note; if another item took one meanwhile, the session is killed and the item re-queued with its attempt given back, the holder named (`Revoke::Requeue`).
- **Refused renewal** (409 stale lease — the record carries another run's lease): the session is killed and the record left untouched, since writing it would end the owning run's locks (`Revoke::Abandon`). A revocation is keyed by (workid, lease), so it can never kill a later run of the same item.
- Tests: `revocations_are_keyed_by_the_runs_lease`, `revoke_kills_the_session_group`, `close_of_a_revoked_run_requeues_or_leaves_the_record_alone`, `lapsed_rows_are_retaken_or_the_run_is_requeued`, `renewal_keeps_a_long_run_holding_its_rows` (updated), `leases_always_enforced_and_leftover_rows_swept`; e2e block "lost locks (2026-09-28): the outage case".
